# 4a: portable memory

## 1. Audit: what each store can do today

Read from `origin/main` of AgentForge (0.5.7) and PrivateAIStack (0.2.0b3).

| Store | List all items | Item IDs | Caller-supplied ID on write | Timestamps | Metadata | Embedding (scheme, default dim) | Delete one item | Export |
|---|---|---|---|---|---|---|---|---|
| Forge `InMemoryVectorStore` | No | `mem_*`, generated | No | None | dict | `agentforge.hashed-bow.blake2b`, **512** | No (`clear` only) | No |
| Forge `SQLiteMemoryStore` | No (table scan inside `search` only) | `mem_*`, generated | No | `created_at` stored, **not returned** | JSON text | same scheme, **64** | No | No |
| Forge `PGVectorMemoryStore` | No | **UUID**, generated by PostgreSQL | No | `created_at` stored, not returned | JSONB | same scheme, **64** (tokenizer copied, not imported) | No | No |
| Forge `ConversationMemory` | `history()` | **none** (`Message` has no id) | n/a | **none** | `Message.metadata` | not embedded | No | No |
| PrivateAIStack `MemoryStore` | `_all_chunks()` (private) | deterministic: `document_id` = sha256 prefix, `chunk_id` = `{document_id}-NNNN` | n/a (derived) | `created_at` | dict | `privateaistack.hashed-bow.sha256-signed`, 64 | Replace only (cascade delete, no tombstone) | `export_jsonl`: unversioned, no schema, includes vectors |

**What a round trip through today's public API loses.** The only write path
is `Memory.add(text, metadata)`, so an import through it:
- **loses every ID** (each backend mints its own; pgvector uses another ID space altogether);
- **loses `created_at`** (never returned by `search`, never accepted by `add`);
- **cannot enumerate the source** at all (`search` is top-k; nothing lists);
- **silently changes vectors** when backends differ in dimension. Forge's three stores share the scheme but not the default dimension, and `SQLiteMemoryStore.search` compares vectors with `zip(..., strict=False)`, so a 64-dim store queried with a 512-dim vector **truncates and returns wrong scores without an error**. This is the concrete failure behind the known issue;
- **conversation memory** loses ordering metadata it never had: no IDs, no timestamps, and `max_messages` truncation drops older turns silently;
- **has no deletion notion**: there is no per-item delete, no tombstone and no `deleted_by_policy` anywhere in either package, so "deleted" cannot be distinguished from "never existed".

**Pre-existing issues found** (reported separately, not fixed inside Phase 4 commits):
1. `SQLiteMemoryStore.search` uses `strict=False`, hiding dimension mismatches (above).
2. `PGVectorMemoryStore` duplicates the tokenizer and hash instead of importing them from `forge.memory.vector`, so the two can drift.
3. The pgvector docstring and `FORGE_PGVECTOR_DSN` error message show a DSN with an inline password (`postgresql://user:pass@host/db`). The DSN is a secret; the URL rule's spirit says credentials come from elsewhere (`PGPASSWORD` / a passfile).
4. PrivateAIStack `export_jsonl` has no version field, no schema, and opens its output path without symlink protection.

## 2. Format: `agent-memory.v1`

Owned by the suite (schema, fixtures, bounded reader), written by AgentForge and
later PrivateAIStack, the same split as `provider-inventory.v1`.

**Embeddings are not stored here.** An `agent-memory.v1` store that has vectors
references an `embedding-portability.v1` document by path and SHA-256, and each
memory item's `item_id` is that inventory's `record_id`. The inventory's
`source_text` digest for the record must equal the item's `content_sha256`,
which binds every vector to the exact memory text it came from. One vector
format, reused.

```json
{
  "schema_version": "agent-memory.v1",
  "generated_by": {"tool": "agentforge-oss", "version": "0.5.8"},
  "export": {
    "export_id": "exp-2026-12-01-a",
    "created_at": "2026-12-01T10:00:00Z",
    "redaction_profile": "standard",
    "source": {"system": "agentforge", "backend": "sqlite", "store_id": "support-memory"}
  },
  "stores": [
    {
      "store_id": "support-memory",
      "kind": "retrieval",
      "embeddings": {
        "inventory": {"path": "embeddings/embedding-portability.json", "sha256": "..."},
        "inventory_store_id": "support-memory"
      },
      "items": {
        "layout": "sharded_jsonl",
        "shards": [{"path": "items/0000.jsonl", "sha256": "...", "record_count": 1000}]
      },
      "counts": {"active": 998, "quarantined": 0, "deleted_by_policy": 2},
      "tombstones": [{"item_id": "mem_7f3a", "deleted_at": "2026-11-30T08:12:00Z"}]
    }
  ]
}
```

One item, one JSONL line, keys in fixed order:

```json
{"item_id": "mem_01", "kind": "document", "text": "...", "content_sha256": "...",
 "metadata": {"topic": "refunds"}, "created_at": "2026-10-02T09:00:00Z",
 "status": "active", "provenance": null}
```

- **`kind`**: `document` (retrieval stores) or `message` (conversation stores). A `message` item adds `sequence`, `role`, `name`, `tool_calls` and `tool_results`; the exporter assigns `item_id` = `msg-{sequence:06d}` because `Message` has none, and says so in the document. `created_at` is `null` where the backend never recorded it; the reader never invents one.
- **`status`**: `active` or `quarantined`. A `deleted_by_policy` item never appears as an item (section 4).
- **`provenance`**: `null` for items native to the exporting system; for items that arrived by import it carries the chain in section 5, so a re-export keeps where everything came from.
- **`store_id`, `item_id`**: `^[A-Za-z0-9._:-]{1,128}$`, unique within a store.
- **Layouts**: `single_file` (items inline, for small stores) and `sharded_jsonl`, exactly the embedding-portability discipline: each shard has its own SHA-256 and `record_count`, **one failed shard invalidates the whole store**.
- **Ordering**: items sorted by `item_id` (by `sequence` for conversations); canonical bytes, so repeating an export of unchanged data produces identical files and digests.
- **No secrets, no locators**: `source` names the system, backend kind and store; never a DSN, file path, URL or credential.

**Bounded parsing** (suite reader and every writer's self-check):

| Limit | Value |
|---|---|
| Document | 4 MiB |
| Shard | 16 MiB; line 64 KiB (an item whose text exceeds 48 KiB is refused: chunk it first) |
| Shards per store / stores / items per store | 1024 / 64 / 100,000 |
| Metadata | depth 8, 64 keys, strings 4 KiB, JSON scalars and containers only |
| Tombstones per store | 100,000 |

Duplicate keys, NaN/Infinity, invalid UTF-8, symlinks, absolute paths and `..`
segments are refused; error messages never repeat a document value.

**Fixtures** (in the suite, placeholder content only): retrieval single-file;
retrieval sharded with an embedding inventory; conversation with tool calls;
store with tombstones; store with quarantined imported items and provenance;
minimal (one item, no embeddings).

## 3. AgentForge API: additive only

Adding abstract methods to `Memory` would break every third-party subclass, so
**`Memory` does not change.** Portability is a separate, optional interface:

```python
@runtime_checkable
class PortableMemory(Protocol):
    async def list_records(
        self, *, after: str | None = None, limit: int = 1000
    ) -> RecordPage: ...
    async def import_records(
        self, records: Sequence[MemoryRecord], *, provenance: ImportProvenance
    ) -> ImportReport: ...
    async def delete_record(self, item_id: str, *, reason: str) -> Tombstone: ...
    async def review_records(
        self,
        item_ids: Sequence[str],
        *,
        decision: Literal["activate", "reject"],
        reviewer: str,
    ) -> ReviewReport: ...
    @property
    def embedding_scheme(self) -> EmbeddingScheme | None: ...
```

- The three bundled backends implement it; a backend that does not is reported as "not exportable" by the CLI, never crashes it.
- `MemoryRecord` is a new model (id, text, metadata, created_at, status, provenance). `MemoryItem` only **gains** an optional `created_at: datetime | None = None`.
- `list_records` pages by `item_id` cursor, so stores of any size stream.
- `import_records` **preserves IDs**; an existing ID with identical content is a no-op (retries are safe), with different content it is refused for that item and reported.
- Storage changes are additive migrations: `CREATE TABLE IF NOT EXISTS` for tombstones, review state and provenance, and a `forge_memory_meta` row recording scheme, revision and dimension. On open, a store whose recorded dimension differs from the configured one is **refused** (fixes D7); a pre-existing store without the row has it written from its first vector's length.
- Module functions `forge.memory.portable.export_memory(...)` / `import_memory(...)` and CLI `forge memory export | import | review | list-quarantine`.
- `search()` keeps its signature and **excludes quarantined items**. Existing data is unaffected because nothing in it is quarantined.
- Release: **agentforge-oss 0.5.8**. Dependents' `<0.6.0` pins keep working. **No breaking change is needed**, so no 0.6.0 chain.

## 4. Privacy and deletion

- **`deleted_by_policy` content is never exported.** A deleted item leaves only a tombstone: `item_id` and `deleted_at`. No text, metadata, digest or vector: even a content digest would let someone confirm a guessed low-entropy value.
- **No resurrection.** Import refuses any item whose ID the target has tombstoned, and any item listed as a tombstone in the export being imported. Both are reported, never silently skipped.
- **Redaction** applies at export through the existing `forge.compliance.redaction` options; the profile name is recorded in the document. The export also runs the secret detectors: an item that still matches a secret pattern **stops the export** and names the item ID (not the value), so the operator redacts or deletes it first.
- **Embeddings follow their text.** A tombstoned item's vector is never exported; the embedding inventory marks that record `deleted_by_policy`, which the suite already understands (and reports `vector retained after source deletion` if a vector survives).

**What an export can promise:** this export contains no content of items
deleted before it ran; text was redacted with the named profile; no credentials
or locators are in it; its bytes match its digests.

**What it cannot promise:** that the source system really deleted anything
(attested); that earlier exports, backups, replicas or provider-side caches no
longer hold the data; that the redaction profile caught every kind of personal
data; or that anyone who already received a copy deleted it.

## 5. Memory poisoning (OWASP ASI06)

Imported memory is **untrusted by default**.

- **Quarantine.** Every imported item lands as `quarantined`: stored, listed, exportable with its status, but **never returned by `search()`** until reviewed.
- **Review.** `forge memory review` activates or rejects items one by one or by export ID. Each decision records the reviewer and time, emits `agentforge.memory.review` to the audit log, and can be gated by an AgentPolicyPack rule on action `memory.import.activate`.
- **Screening.** Import runs `InputSanitizer` over every item's text and metadata. Flagged items can only be activated one at a time with `--accept-flagged`; bulk activation skips them.
- **Provenance per item**, kept in its own column, never in user metadata: source system and store, export ID, export SHA-256, original item ID, import time and importer version. Import refuses items whose metadata contains reserved `_forge_*` keys, so a document cannot forge provenance.
- **Never promoted into system prompts.** No Forge code path reads memory into a prompt today. The rule becomes a test: retrieved memory is only ever rendered as quoted, labeled context in a non-system message, and a test asserts no `Role.SYSTEM` message is built from memory text.

## 6. Letta Agent File (`.af`)

Sources: the agent-file and letta repositories and Letta's docs (read
2026-11-25). **License: Apache-2.0** for both repositories, so compatible.

Material facts:
- Letta's own docs now say **Letta Code and Letta Cloud no longer support `.af` import or export**; the schema lives on the letta repo's `archive` branch.
- **No version field** and **no published JSON Schema**; only a Python (pydantic) definition.
- **Archival memory (passages) is not included**: on Letta's roadmap, not in the format. No embedding vectors anywhere.
- Secrets are exported as `null`; MCP server records drop tokens, headers and stdio env.

| `.af` element | Into Forge | Lost |
|---|---|---|
| `messages` (id, role, content, tool_calls, tool_returns, created_at) | `message` items, IDs remapped, original ID in provenance | approval fields |
| `in_context_message_ids` | ordering hint | which messages were in context |
| core memory `blocks` (label, value, limit, read_only) | `document` items, quarantined | **semantics**: in Letta blocks are part of the system prompt; Forge never puts imported memory there (section 5) |
| `tools` (with **source code**) | nothing executable: never imported or run; name and schema recorded only | all tool behaviour |
| `mcp_servers` | candidate entries for a tool approval file, default-deny | credentials (already stripped) |
| `llm_config`, `embedding_config` | provenance metadata only | everything else |
| `tool_rules`, groups, files, sources, skills | nothing | all |

The other direction, Forge to `.af`, would lose retrieval memory entirely (no
passages in `.af`), every vector, all provenance and tombstones.
**Recommendation:** an import-only adapter (`forge memory import --from-letta-af`)
that parses with the standard library (no `letta` dependency), refuses files
over 16 MiB, routes everything through quarantine, and prints the loss table
above for every import. Given the format is retired upstream, it is the last
checkpoint of 4a and can be dropped without affecting anything else.

## 7. Suite: the memory vector

New manifest state `memory_inventory`, accepted only on `memory`: path and
SHA-256 of an `agent-memory.v1`, plus an optional `import_report` (path and
SHA-256 of an `agent-memory-import.v1` written by the importing system).

**The scanner verifies itself:** schema and bounds; every shard digest and
`record_count`; item ID uniqueness; counts by status; tombstones carry no
content; no tombstoned ID appears as an item; `content_sha256` of every item
re-hashed; when embeddings are linked, that the inventory exists at its digest,
names the store, has a record for every active item, and its source-text digest
equals the item's `content_sha256`; and a **format round trip**: parse, re-serialize
canonically, same bytes. The suite never imports AgentForge; AgentForge's
`suite-contract` job validates every variant its writer emits.

**Stays attested:** that the export is complete, that deletions happened, that
redaction was adequate, `created_at` values, provenance claims, and that any
importer works at a destination.

| Score (per store; worst store governs) | Condition |
|---|---|
| 0 | **Unreachable in this design** (never on attested evidence). Reserved for a future scanner-run restore. |
| 25 | Verified export, embeddings (if any) linked with full coverage, **and** an import report bound to this export's digest whose counts match (the import is attested; the binding is verified). |
| 50 | Verified export alone: "portable export only". |
| 100 | Invalid or missing evidence. |

Level `verified (memory export)` (D2) when the scanner re-read everything;
`attested` items listed in `attested_claims`, as for the other vectors.

# 4b: MCP tool connectors

## 8. Audit: tools today

- `Tool` wraps a Python callable with a name, description, JSON Schema `parameters` and a `dangerous` flag; `ToolRegistry.register` **replaces a same-named tool silently** (an in-process rug pull nobody would see).
- `ToolSandbox` enforces allow/deny lists, denies dangerous tools by default, applies a timeout, consults Forge's own `PolicySet` and emits events.
- `InputSanitizer` screens inputs for injection indicators; tool **results** are plain strings and are not marked untrusted.
- Built-ins: `calculator`, `time`, `http_get` (dangerous).
- **No MCP support anywhere** in AgentForge.
- AgentPolicyPack requests already carry a free-form `tool` object (`name`, `namespace`, `capabilities`, ...), so MCP rules need **no AgentPolicyPack code change**.
- AIAuditLog reserves `tool.*` and `security.*` for core types but accepts namespaced custom event types.

## 9. Design: MCP-first

- **`forge.tools.mcp.McpConnector`** connects to one server (Streamable HTTP or stdio), calls `server/discover` and `tools/list`, and wraps each remote tool as an `McpTool(Tool)`. Every `McpTool` is `dangerous=True` and gated by approval (section 10).
- **`forge.tools.mcp.serve`** exposes a `ToolRegistry` as an MCP server, so the built-in tools are reachable through MCP too.
- **`ToolConnector` adapter protocol** for proprietary connectors: `describe()` and `call()`, mounted behind an in-process MCP server. Every external tool then passes the same definition hashing and approval, whatever it wraps.
- **Spec target 2026-07-28**: no sessions (protocol version and capabilities ride in each request's `_meta`), `server/discover` required, change notices through `subscriptions/listen`. A `toolsListChanged` notice triggers re-hashing, never auto-acceptance.
- **Not built**: roots, sampling and logging (deprecated); the HTTP+SSE transport (deprecated); the tasks extension. Elicitation is not used initially.
- **Authorization**: RFC 9728 Protected Resource Metadata for discovery; RFC 8707 `resource` on every authorization and token request; RFC 9207 `iss` checked by exact string comparison before redeeming a code; Client ID Metadata Documents, not dynamic client registration. Tokens come from the environment or a secret store, never config, logs, events or exports.

**SDK (needs your approval as a new dependency):** `mcp` **2.3.0** on PyPI
(2026-10-02), **MIT**, Python `>=3.10`, listed as **Tier 1** ("fully
supported") on modelcontextprotocol.io. Its dependency set is heavy:
starlette, uvicorn, sse-starlette, pyjwt[crypto], python-multipart,
opentelemetry-api, jsonschema, pydantic>=2.12, `httpx2` (a package distinct
from the `httpx` Forge already uses), pywin32 on Windows, and an exactly pinned
`mcp-types`.

| Option | For | Against |
|---|---|---|
| **A. optional extra `agentforge-oss[mcp]` = `mcp>=2.3,<3`** | Tier 1 maintenance; OAuth, discovery and `iss` handled by the reference implementation | Heavy tree, but only for users who opt in; the pydantic floor may lift resolved versions |
| B. in-house client on `httpx` | No new dependency | We own OAuth and `iss` logic: the riskiest code to hand-write |
| C. defer 4b | Nothing new | No progress on the vector |

**Recommendation: A**, with a gate at checkpoint 4b-1: confirm `mcp` 2.3.0
implements the 2026-07-28 revision (`server/discover`, no session handshake)
before writing anything on it. If it does not, stop and report.

## 10. Security

**Rug-pull defense.**
- **Definition hash** = SHA-256 of RFC 8785 canonical JSON of `{server_id, name, description, inputSchema, outputSchema, annotations}` (D6).
- **Approvals live in Git** as a `tool-approvals.v1` file (version field, JSON Schema, fixtures): server ID, server origin (origin only), tool name, definition hash, approver and date. Definitions are defined in the repo; servers are only where they run.
- **On connect and on every list change, each tool is either:** `approved` (hash matches); `pending` (unknown: refused, default deny); or `changed` (hash differs: **refused** until re-approved).
- A `changed` tool emits `agentforge.mcp.tool_definition_changed` with both hashes, never the description text, recorded in AIAuditLog.
- A tool that disappears is refused if it returns. A same-named tool from another server is a different identity.

**Untrusted input.**
- Descriptions and schemas are screened by `InputSanitizer` at approval. Flagged definitions need `--accept-flagged` per tool.
- Text reaching a model is capped (description 1 KiB) with control characters stripped, and is never placed in a system message.
- Input schemas are bounded (depth, size, no remote `$ref`) and arguments are validated against them before sending.
- Results become `ToolResult`s marked untrusted, are capped, and are screened. A flag emits an event.
- Server error text follows the 0.5.6 rule: only the exception class reaches prompts, events or audit records.

**Endpoints and secrets.**
- MCP endpoint URLs follow the URL rule: no credentials, query or fragment; required parameters go in `default_query`, redacted everywhere. Endpoints are recorded by origin only, with hosting derived by the shared locality rule.
- stdio servers are launched from an argument list (no shell) with an environment allowlist; secrets are referenced by environment-variable name.

**Default deny.** A server not named in configuration and permitted by policy
is never contacted. A tool not in the approval file is never offered to a
model.

**AgentPolicyPack rule.**
- Forge builds requests with action `mcp.server.connect` (resource type `McpServer`, with server ID, origin and derived hosting) and `tool.call`, where `tool.namespace` = `mcp.<server_id>` and `tool.definition_sha256` is set.
- An example bundle `examples/mcp_governance/` with embedded tests (deny by default, allow listed servers, deny one tool, require review for hosted servers) ships in AgentPolicyPack. No code change there.

## 11. Suite: the tool_connectors vector

New state `tool_inventory`, accepted only on `tool_connectors`, referencing
`tool-inventory.v1` (written by `forge tools inventory`) and optionally the
`tool-approvals.v1` file.

```json
{"schema_version": "tool-inventory.v1",
 "generated_by": {"tool": "agentforge-oss", "version": "0.5.9"},
 "tools": [{"tool_id": "files_search", "name": "search", "server_id": "files",
            "transport": "mcp_streamable_http", "server_origin": "http://127.0.0.1:8765",
            "definition_sha256": "...", "portability": "mcp",
            "reconstruction": null}]}
```

- `transport`: `in_process`, `mcp_stdio` or `mcp_streamable_http`. `portability`: `mcp` or `vendor_only`. `reconstruction`: `documented`, `none`, or `null` for MCP tools.
- **The scanner verifies itself:** schema and bounds; digests; credential-free origins; hosting derived from each origin; hash format and uniqueness; and, if an approval file is supplied, that every inventoried hash is approved and none is stale.
- **Stays attested:** that any tool works, that an MCP server is really self-hostable, reconstruction paths, and that descriptions are benign.

| Score (per tool; worst governs) | Condition |
|---|---|
| 0 | Unreachable (attested evidence never scores 0). |
| 25 | Exposed or consumed via MCP, hash approved, server endpoint derived as local or in-process. |
| 50 | Via MCP but the server is hosted, or the hash is not approved; the reason names which. |
| 75 | `vendor_only` with `reconstruction: documented`. |
| 100 | `vendor_only` with no reconstruction, or no inventory. |

## 13. Fakes and negative tests

**Everything offline.** A test-wide guard fails any socket connect, so a test
that reaches the network fails rather than passes.

**Fake MCP servers**: in-process, in-memory transport, implementing `server/discover`, `tools/list` and `tools/call`.

| Fake | What it proves |
|---|---|
| `honest` | Approved tools run; results come back marked untrusted. |
| **`rug_pull`** | After approval, changes a description, then an input schema, then only an annotation. Each time the tool is refused, an audit record carries both hashes, and re-approval restores it. |
| **`poisoned_description`** | Description with an instruction-override and data-exfiltration lure. Flagged at approval, refused without `--accept-flagged`, never placed in a system message, capped. |
| `poisoned_result` | Injection text in a result: flagged, capped, marked untrusted. |
| `leaky_error` | Error containing a planted secret: the secret appears in no prompt, event, log or audit record. |
| `remote_ref` / `huge_schema` | Remote `$ref` and over-bound schemas refused. |
| `deprecated_sampling` | A server-to-client sampling request is refused. |
| `name_collision` | Same tool name from two servers: two identities, two approvals. |
| `list_changed_storm` | Repeated change notices: re-hashing only, no auto-approval. |

**Fake memory backends:** `FakePortableStore`; a **legacy third-party `Memory`
subclass** implementing only `add`, `search` and `clear` (proves the change is
additive: it still works and is reported "not exportable"); a store with a
mismatched dimension.

**Negative tests, memory:**
- wrong or missing `schema_version`; unknown keys; duplicate keys; NaN; over-size document, shard, line or metadata; symlinked or escaping paths; a shard digest mismatch invalidates the store;
- duplicate item IDs;
- a tombstone that carries content, or a tombstoned ID present as an item;
- `content_sha256` mismatch;
- a linked embedding record missing, or whose source digest differs;
- conversation items out of sequence;
- reserved `_forge_*` metadata on import;
- import of a tombstoned ID (refused, reported);
- the same ID with different content (refused); with the same content (no-op);
- quarantined items never returned by `search`;
- bulk activation skips flagged items;
- a secret-matching item stops the export, and the error names the ID only;
- a dimension mismatch refuses the store on open;
- no DSN, path or credential in any export;
- re-export of imported items keeps provenance;
- the round trip leaves bytes unchanged;
- the score is never 0, and 25 needs a digest-bound import report.

**Negative tests, tools:**
- unknown server never contacted; unknown tool never offered;
- each hashed field changing refuses the tool;
- a removed tool that returns stays refused;
- a credential, query or fragment in an endpoint is refused;
- tokens absent from config, events and exports;
- an `iss` mismatch or missing `iss` (when advertised) stops authorization;
- a token for another audience is refused;
- the policy bundle denies by default;
- `tool-inventory.v1` bounds and duplicates;
- a stale approval (hash not in the inventory) is reported;
- a vendor-only tool with no reconstruction scores 100;
- the score is never 0.
